# Gooo IR Metaprogramming Lab

An experiment in splitting code generation into three jobs:

1. a planner records the task as bounded semantic rules;
2. Laya selects a construction route from a small, named set;
3. deterministic Gooo and Go emitters assemble and validate the result.

Laya chooses a route; it never writes source code. With Laya unavailable,
`gooo decide` selects the declared deterministic fallback. A hash-seeded
probability sample is also reported to compare top-1 routing with probabilistic
composition while remaining replayable.

## The 100-experiment matrix

The companion [experiment repository](https://github.com/kimjooyoon/gooo-metaprogramming-experiments)
contains ten decision intents and ten lowering routes, giving 100 distinct
intent/route experiments. Each candidate is compiled and run against every
point in the declared input domain. The domain, expected rules, Laya receipt,
and output digests are saved in the report.

```sh
GOOO_BIN=/path/to/gooo go run ./cmd/lab matrix \
  --plan ../gooo-metaprogramming-experiments/plan-v1.json \
  --out artifacts/matrix
```

Set `GOOO_LAYA_URL=http://127.0.0.1:8787/v1/systemone` to use a running local
Laya service. Omit it for deterministic fallback. Model weights stay in the
local Hugging Face cache and are never included in either Git repository.

## What the prototype generates

The runner asks the current Gooo CLI to generate the semantic declaration
projection, then emits the experimental `if`/condition/assignment body
patterns into a companion Go file. It does not extend the stable `.gooo`
grammar or claim that current `gooo generate` compiles executable activity
bodies. The matrix tests the proposed lowering boundary before any language
surface or compiler change is promoted.

## Metrics

- Finite-domain behavioral agreement: matched outputs / all declared input
  points, reported with its domain and not presented as a proof for all inputs.
- Rule-clause completeness: fully satisfied reachable rules and fallback /
  reachable clauses. A missing branch is visible even when many samples pass.
- Construction coverage and precision: intended Go AST constructs present /
  expected constructs, and expected constructs / constructs actually emitted.
- Compilation, two-pass source digest equality, Laya decision probability,
  deterministic weighted-sample choice, latency, and generated byte counts.

These values remain a vector. A high completeness percentage cannot hide a
failed compile, a missing branch, or nondeterministic output.
