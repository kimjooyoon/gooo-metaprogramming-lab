# Compiler-integrated body-codegen cohort plan

Status: planned; not yet measured. The existing 100-case corpus remains the
sidecar baseline. This cohort will exercise the language repository's
`gooo body-codegen` command directly after its Laya routing change passes CI and
is published on the default branch.

## Question

Can a bounded Laya decision select a useful Go control-flow shape after Gooo
has parsed and typechecked the source body, while deterministic lowering keeps
behavior, completeness, and replay stable?

This is a compiler-structure experiment, not a claim that a model should write
programs. Laya receives the bounded route question and structural metadata; it
does not receive the activity body. The compiler owns parsing, typechecking,
emission, and fallback.

## Frozen cohort: 100 source programs

Build 10 small semantic families with 10 boundary/constant variants each. Each
fixture stays in the current body-codegen profile: one `Integer` or `Boolean`
input, local values where needed, one pure `if/else`, and one return in each
branch. Candidate families include threshold classification, lower and upper
clamps, inclusive and exclusive ranges, sign mapping, Boolean gating, and
conditional integer adjustment. Keep constants inside the declared test
domains and store an independent expected-result function with each case.

The matrix has 100 unique source digests. For every source, evaluate these
three named routes when the shape permits them:

1. `preserve`: keep both branch returns;
2. `guard-return`: return from the true branch, then emit the false-branch
   return after the `if`;
3. `merge-result`: assign both branch values to a typed local and return it
   after the join.

All three candidates should be semantically equivalent for this profile. If
one fails to parse, typecheck, compile, replay, or match the independent oracle,
record the failure and keep it out of the oracle's eligible set. Never repair a
candidate by hand during measurement.

## Comparison arms

- **Deterministic baseline:** `preserve` with Laya unconfigured.
- **Laya top-1:** the route returned by the pinned local Laya checkpoint.
- **Seeded probability:** sample the reported route probabilities with a
  versioned seed and record the selected probability. This is a separate arm,
  never an implicit compiler default.
- **Candidate oracle:** choose the best candidate that passes every hard gate
  under a declared structural preference. This is an evaluation upper bound,
  not a deployable selector.

Run the actual Laya decision once per unique source in the scored cohort. Also
run deterministic fallback twice per source and require identical selected
route and output digests. Record cold model-load latency separately from warm
inference; do not count Go process startup as model latency.

## Completeness and quality vector

Keep the measures separate so a high score cannot hide a failed artifact.

| Measure | Definition | Gate or interpretation |
| --- | --- | --- |
| Source construct coverage | lowered supported statements and expressions / source statements and expressions | Per-case completeness ratio; retain missing IDs |
| Branch-return coverage | represented reachable returns / expected reachable returns | Must be 100% for an accepted artifact |
| Typecheck | generated function passes Go type checking | Hard gate |
| Compile and execute | generated candidate builds and executes in the fixture harness | Hard gate |
| Finite-domain behavior | oracle-matching input/output pairs / all declared inputs | Report numerator, denominator, domain, and worst case |
| Replay | identical report and source digests across repeated generation | Hard gate |
| Route decision | selected ID, full allowed set, probabilities, checkpoint revision | Routing evidence, not correctness evidence |
| Selection gain | selected structural preference minus deterministic `preserve` | Zero means inference added no measured structure value |
| Oracle gap | oracle structural preference minus selected preference | Describes remaining candidate-selection headroom |
| Latency and resources | decision p50/p95/p99, CPU time, peak RSS, generated bytes | Report warm and cold paths separately |

Aggregate counts and numerators over all 100 cases, and include per-family and
worst-case results. Do not average percentages with unequal denominators. Keep
semantic behavior and emitted-structure completeness distinct: because these
routes are intended to be equivalent, a 100% behavior score alone cannot show
that Laya helped.

## Reporting and promotion rule

Save one immutable JSON record per case with the source, request, decision,
checkpoint, candidate, and output digests; the full metric denominators; and
failure or fallback reasons. Publish the plan hash, corpus version, seed,
toolchain, machine CPU/RAM, and Laya revision with the aggregate report.

Keep Laya routing experimental unless the frozen cohort shows a repeatable
benefit in the declared structural preference or another explicit system
utility, while compile, typecheck, finite-domain behavior, replay, and fallback
remain unchanged and resource cost stays within its budget. If Laya selects
`preserve` throughout, or adds latency without a measurable structural gain,
record that as a negative result and retain deterministic routing as the
default.
